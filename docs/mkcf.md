# mkcf - CMakeLists.txt Generator for Fortran/C Projects

`mkcf` is a drop-in replacement for `mkmf` that generates `CMakeLists.txt` files
instead of traditional Makefiles. It enables scientific computing projects using
Fortran and C to transition from make-based builds to modern CMake-based builds.

## Overview

`mkcf` (make cmake file) provides the same functionality as `mkmf` but outputs
CMakeLists.txt files compatible with CMake 3.18+. It automatically:

- Scans Fortran files for module definitions and use statements
- Resolves module dependencies
- Parses mkmf template files for compiler configurations
- Generates CMake configuration with multiple build types (PROD, REPRO, DEBUG, TEST)
- Supports OpenMP, code coverage, and NetCDF options
- Handles C preprocessing of Fortran source files (--use-cpp)

### Why CMake?

Transitioning from Make to CMake provides several benefits:

- **Better IDE integration**: Most modern IDEs support CMake natively
- **Cross-platform builds**: CMake generates appropriate build files for any platform
- **Improved dependency management**: CMake handles Fortran module dependencies automatically
- **Modern features**: Support for parallel builds, installation targets, and testing frameworks
- **Easier maintenance**: CMake configurations are more readable and maintainable

## Installation

### Using Conda (Recommended)

```bash
# Create and activate the mkcf environment
conda env create -f environment.yml
conda activate mkcf

# Make mkcf executable
chmod +x bin/mkcf
```

### Manual Installation

Requirements:
- Python 3.9+
- click package

```bash
# Install click
pip install click

# Make mkcf executable
chmod +x bin/mkcf

# Add to PATH (optional)
export PATH=/path/to/mkmf/bin:$PATH
```

## Quick Start

Here's a simple example of using `mkcf`:

```bash
# 1. Generate pathnames file using list_paths
list_paths -l -o pathnames_mylib /path/to/source

# 2. Generate CMakeLists.txt using mkcf
mkcf -t templates/linux-gnu.mk \
     -p libmylib.a \
     -c "-DUSE_NETCDF -DINTERNAL_FILE_NML" \
     pathnames_mylib

# 3. Build with CMake
mkdir build && cd build
cmake -DPROD=ON ..
make -j8
```

## Command-Line Interface

```
mkcf [OPTIONS] [TARGETS]...
```

### Options

| Option | Description |
|--------|-------------|
| `-a, --abspath PATH` | Absolute path prefix for relative paths |
| `-b, --blddir PATH` | Build directory path |
| `-c, --cppdefs TEXT` | CPP definitions (e.g., '-DUSE_NETCDF -DDEBUG') |
| `-d, --debug` | Enable debug output |
| `-I, --includes PATH` | Include directories (can be specified multiple times) |
| `-l, --linkflags TEXT` | Additional linker flags |
| `-m, --makefile PATH` | Output file name (default: CMakeLists.txt) |
| `-o, --otherflags TEXT` | Additional compiler flags |
| `-p, --program TEXT` | Target name (library.a or executable) |
| `-t, --template PATH` | mkmf template file for compiler configuration |
| `-v, --verbose` | Enable verbose output |
| `-x, --execute` | Execute cmake after generating CMakeLists.txt |
| `--use-cpp` | Use C preprocessor for .F90 files |
| `--version` | Show version and exit |

### Arguments

`TARGETS` can be:
- Directories containing source files
- Individual source files
- Pathnames files (generated by `list_paths`)

## Build Options

The generated CMakeLists.txt supports several build options that can be passed
to CMake:

### Build Types (Mutually Exclusive)

```bash
cmake -DPROD=ON ..        # Production/optimization build (default)
cmake -DREPRO=ON ..       # Reproducibility build
cmake -DDEBUG_BUILD=ON .. # Debug build
cmake -DTEST_BUILD=ON ..  # Test build
```

### Additional Options

```bash
cmake -DOPENMP=ON ..      # Enable OpenMP support
cmake -DCOVERAGE=ON ..    # Enable code coverage
cmake -DNETCDF=3 ..       # Use NetCDF 3 compatibility mode
cmake -DUSE_R4=ON ..      # Use single precision reals
cmake -DVERBOSE=ON ..     # Enable verbose output
```

### Combining Options

```bash
cmake -DPROD=ON -DOPENMP=ON ..
```

## Template Files

`mkcf` parses mkmf template files to extract compiler configurations. Template
files are standard makefile fragments that define variables like:

```makefile
# Compilers
FC = gfortran
CC = gcc
LD = gfortran

# Base flags
FFLAGS := -fdefault-real-8 -ffree-line-length-none
CFLAGS := -D__IFC

# Build type flags
FFLAGS_OPT = -O3
FFLAGS_REPRO = -O2
FFLAGS_DEBUG = -O0 -g -fbounds-check

# OpenMP flags
FFLAGS_OPENMP = -fopenmp
LDFLAGS_OPENMP = -fopenmp
```

### Supported Template Variables

| Variable | Description |
|----------|-------------|
| `FC` | Fortran compiler command |
| `CC` | C compiler command |
| `CXX` | C++ compiler command |
| `LD` | Linker command |
| `FFLAGS` | Base Fortran flags |
| `FFLAGS_OPT` | Optimization Fortran flags |
| `FFLAGS_REPRO` | Reproducibility Fortran flags |
| `FFLAGS_DEBUG` | Debug Fortran flags |
| `FFLAGS_TEST` | Test Fortran flags |
| `FFLAGS_OPENMP` | OpenMP Fortran flags |
| `CFLAGS` | Base C flags |
| `CFLAGS_OPT` | Optimization C flags |
| `CFLAGS_REPRO` | Reproducibility C flags |
| `CFLAGS_DEBUG` | Debug C flags |
| `CFLAGS_OPENMP` | OpenMP C flags |
| `LDFLAGS` | Base linker flags |
| `LDFLAGS_OPENMP` | OpenMP linker flags |
| `LIBS` | Libraries to link |

## Preprocessing Fortran Files

The `--use-cpp` option enables C preprocessing of Fortran source files before
compilation. This is useful when:

- Fortran files contain complex C preprocessor macros
- The compiler's built-in preprocessor has limitations
- You need to generate intermediate files for debugging

### How It Works

When `--use-cpp` is enabled:

1. `.F90` and `.F` files are preprocessed using the C preprocessor (cpp)
2. Output files are named `<basename>.DO_NOT_MODIFY.f90`
3. The preprocessed files are compiled instead of the original sources
4. CMake automatically handles dependency tracking

### Example

```bash
# Generate with preprocessing enabled
mkcf --use-cpp \
     -t templates/linux-gnu.mk \
     -p libland.a \
     -c "-DINTERNAL_FILE_NML -nostdinc" \
     pathnames_land
```

This generates CMake rules that:

```cmake
if(USE_CPP)
    # Find C preprocessor
    find_program(CPP_EXECUTABLE cpp)
    
    # Preprocess each .F90 file
    add_custom_command(
        OUTPUT ${_output_file}
        COMMAND ${CPP_COMMAND} -nostdinc -C ${CMAKE_C_FLAGS}
            $<TARGET_PROPERTY:land,COMPILE_DEFINITIONS>
            ${_input_file} > ${_output_file}
        DEPENDS ${_input_file}
    )
endif()
```

## Migration from mkmf

### Direct Replacement

In most cases, you can replace `mkmf` with `mkcf` directly:

```bash
# Before (mkmf)
mkmf -m Makefile -a $src_dir -b $bld_dir -p libFMS.a -t $template \
     -c "-DUSE_NETCDF" pathnames_FMS

# After (mkcf)
mkcf -m CMakeLists.txt -a $src_dir -b $bld_dir -p libFMS.a -t $template \
     -c "-DUSE_NETCDF" pathnames_FMS
```

### Build Commands

Replace make commands with CMake equivalents:

```bash
# Before (Make)
make PROD=on OPENMP=on

# After (CMake)
mkdir build && cd build
cmake -DPROD=ON -DOPENMP=ON ..
make
```

### Example: Complete Migration

Original mkmf-based build:

```bash
# Generate Makefile
mkmf -m Makefile -a $src_dir -b $bld_dir -p libFMS.a \
     -t ncrc5-intel.mk \
     -c "-DHAVE_GETTID -DUSE_NETCDF" \
     -IFMS/include \
     pathnames_FMS

# Build
make PROD=on OPENMP=on -j8
```

CMake-based build:

```bash
# Generate CMakeLists.txt
mkcf -m CMakeLists.txt -a $src_dir -b $bld_dir -p libFMS.a \
     -t ncrc5-intel.mk \
     -c "-DHAVE_GETTID -DUSE_NETCDF" \
     -IFMS/include \
     pathnames_FMS

# Build
mkdir build && cd build
cmake -DPROD=ON -DOPENMP=ON ..
make -j8
```

## Examples

### Building a Library

```bash
# Generate pathnames
list_paths -l -o pathnames_FMS src/FMS

# Generate CMakeLists.txt
mkcf -t templates/linux-gnu.mk \
     -p libFMS.a \
     -c "-DUSE_NETCDF -DINTERNAL_FILE_NML" \
     -IFMS/include \
     pathnames_FMS

# Build
cmake -DPROD=ON .
make -j8
```

### Building an Executable

```bash
mkcf -t templates/linux-gnu.mk \
     -p mymodel \
     -c "-DUSE_MPI" \
     -o "-I/path/to/includes" \
     -l "-lnetcdf -lmpi" \
     src/

cmake -DDEBUG_BUILD=ON -DOPENMP=ON .
make
```

### Using with External Dependencies

```bash
mkcf -t templates/ncrc5-intel.mk \
     -p libatmos.a \
     -c "-DINTERNAL_FILE_NML" \
     -o "-I$bld_dir/FMS -I$bld_dir/physics" \
     -IFMS/include \
     pathnames_atmos
```

### Complete AM5-style Build

```bash
bld_dir=/path/to/build
src_dir=/path/to/source
template=/path/to/template.mk

# Build FMS library
mkdir -p $bld_dir/FMS
list_paths -l -o $bld_dir/FMS/pathnames_FMS $src_dir/FMS
cd $bld_dir/FMS
mkcf -a $src_dir -b $bld_dir -p libFMS.a -t $template \
     -c "-DHAVE_GETTID -DUSE_NETCDF" \
     -IFMS/include \
     pathnames_FMS

cmake -DPROD=ON -DOPENMP=ON .
make -j8

# Build physics library
mkdir -p $bld_dir/physics
list_paths -l -o $bld_dir/physics/pathnames_physics $src_dir/physics
cd $bld_dir/physics
mkcf -a $src_dir -b $bld_dir -p libphysics.a -t $template \
     -c "-DINTERNAL_FILE_NML" \
     -o "-I$bld_dir/FMS" \
     pathnames_physics

cmake -DPROD=ON -DOPENMP=ON .
make -j8
```

## API Reference

### Main Functions

#### `parse_template(template_path: Path) -> TemplateConfig`

Parse a mkmf template file and extract configuration.

**Parameters:**
- `template_path`: Path to the mkmf template file

**Returns:**
- `TemplateConfig` object with compiler settings and flags

#### `scan_file_for_dependencies(file_path: Path) -> SourceFile`

Scan a source file for module definitions, uses, and includes.

**Parameters:**
- `file_path`: Path to the source file

**Returns:**
- `SourceFile` object with dependency information

#### `collect_sources(targets, abs_path, include_dirs) -> tuple`

Collect all source files from targets.

**Parameters:**
- `targets`: List of directories, files, or pathnames files
- `abs_path`: Optional absolute path prefix
- `include_dirs`: Additional include directories

**Returns:**
- Tuple of (source files list, include directories list)

#### `generate_cmakelists(...) -> str`

Generate CMakeLists.txt content.

**Parameters:**
- `sources`: List of SourceFile objects
- `include_dirs`: Include directories
- `program_name`: Target name
- `cppdefs`: CPP definitions
- `other_flags`: Additional compiler flags
- `link_flags`: Additional linker flags
- `template_config`: Template configuration
- `src_root`: Source root directory
- `build_root`: Build root directory
- `use_cpp`: Enable C preprocessing
- `verbose`: Enable verbose output

**Returns:**
- String containing CMakeLists.txt content

### Data Classes

#### `SourceFile`

Represents a source file with metadata and dependencies.

**Attributes:**
- `path`: Absolute path to the file
- `name`: Base name without extension
- `suffix`: File extension
- `object_name`: Object file name
- `modules_defined`: List of modules defined
- `modules_used`: List of modules used
- `includes`: List of include files
- `requires_cpp`: Whether file needs preprocessing

#### `TemplateConfig`

Configuration from mkmf template file.

**Attributes:**
- Compiler commands: `fc`, `cc`, `cxx`, `ld`
- Fortran flags: `fflags_base`, `fflags_opt`, `fflags_repro`, etc.
- C flags: `cflags_base`, `cflags_opt`, `cflags_repro`, etc.
- Linker flags: `ldflags`, `ldflags_openmp`
- Other: `libs`, `cppdefs`, `includes`

## Testing

### Running Tests

```bash
# Install test dependencies
conda activate mkcf

# Run all tests
pytest t/test_mkcf.py -v

# Run with coverage
pytest t/test_mkcf.py -v --cov=bin/mkcf --cov-report=html

# Run specific test class
pytest t/test_mkcf.py::TestSourceFileScanning -v

# Run specific test
pytest t/test_mkcf.py::TestCLI::test_cli_basic_run -v
```

### Test Categories

- **TestSourceFileScanning**: Tests for scanning source files
- **TestTemplateParsing**: Tests for parsing template files
- **TestSourceCollection**: Tests for collecting sources from targets
- **TestCMakeGeneration**: Tests for generating CMakeLists.txt
- **TestCLI**: Tests for command-line interface
- **TestIntegration**: End-to-end integration tests
- **TestEdgeCases**: Error handling and edge cases
